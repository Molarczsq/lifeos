# 用户名注册流程更新

## 行为
用户名 + 密码 + 服务端图案验证码注册到数据库，成功后自动签发会话Cookie。登录只需用户名和密码。刷新页面通过Cookie恢复账户，再加载该账户的数据库记录；退出后私有缓存清空。未登录时不渲染导航和AI入口。

## 兼容旧数据库
启动时将 users.email 原地重命名为 username，不改变用户ID、密码哈希、会话或健康记录。旧账户继续用原完整邮箱登录。迁移可重复运行，SQLite迁移测试已通过；生产升级前保留数据库备份。不要执行 docker compose down -v。

## 验证记录
本地完整后端测试29项通过；Next.js生产构建和TypeScript检查通过。覆盖验证码一次性使用、过期、绑定、用户名大小写、密码比对、Cookie轮换/注销、跨用户隔离和旧数据库迁移。

已新增2条移动端E2E：正常注册→记录→聊天→刷新→退出→重新登录恢复记录→另一账户隔离；错误验证码拒绝后刷新并重试。对应云端结果以当前提交的GitHub Actions为准。

## 验证与推送脚本修复
之前脚本没有持久日志；网络/认证检查失败或测试挂起时，不能仅凭终端返回判断已经推送。当前环境曾复现域名解析失败和套接字通信被禁止，恢复网络授权后完整本地测试通过。由于之前用户终端输出未留存，无法断言那一次具体退出在哪一行。

现在执行 `bash scripts/verify-and-push.sh`：先确认网络与认证，运行完整后端测试和前端构建，通过后才推送，核对远程提交，再等待该提交的GitHub Actions（包括E2E）。失败提示阶段；日志在 `.verification-logs/`（Git忽略），后端测试默认180秒超时。脚本不会启动部署或删除数据库。
