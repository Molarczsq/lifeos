# 怎么做菜：纯模型菜谱推荐

## 定位

一条轻量入口：用户勾选手里的食材，填口味、可用时间、份数与忌口，由已配置的 OpenAI 兼容模型
一次性生成 1–3 道菜，每道给出用料、分步做法与每步火候。它不替代项目里已有的生成式饮食工作流
（`ai_services.py` 的 Recipe / 确认动作 / 顾问编排），只补「我手里有这些菜，现在怎么炒」这条交互。
若维护者认为与既有能力重复，直接不合并即可。

## 契约

- `POST /api/v1/recipes/recommend`，请求 `RecipeRequest`，响应 `RecipePlan` 对应的公开结构。
- 服务端把用户食物目录的 `food_id` / `name` 放进提示词，模型返回的 `items[].food_id`
  只保留目录中真实存在的项；其余菜仍展示做法，但不提供「记录这餐」按钮。
- 输出经 JSON Schema 校验与 `review_answer` 安全复核；复核不通过按模型不可用处理。
- 每条结果标注 `source: live-model`，`mode: live-model`，`estimated: true`。

## 必须连接模型，没有本地兜底

未配置 `LLM_API_KEY`、未开启 `external_ai` 授权、模型失败或输出被复核拦截，
接口一律返回 503 并给出中文说明。这一步是刻意的：不把确定性规则或内置菜谱库的结果
呈现为模型生成。此前 PR #2 的「无密钥离线降级」方案已被本方案取代。

## 边界

模型输出未经人工逐条核验；份量与营养均为估计，调味料与另备食材未计入；
忌口由模型按要求排除，服务端无法核实别名、调味料成分与交叉接触风险，食用前需自行确认。
