# 怎么做菜

用户自由输入已有食材，支持中文、英文及常见别名，逗号批量添加、Enter 添加、编辑、删除和可选数量单位。目录选项仅作快捷输入，不限制自定义食材。

## API

`POST /api/v1/recipes/recommend` 保留旧 `ingredients` 字段，新增 `pantry`（name / quantity / unit）、`excluded`、`equipment`、`difficulty`、`adjustment` 和 `previous_id`。时间、份数、口味和过敏原继续有效。

服务端合并并去重食材，将本次库存、排除项、厨具与难度传给模型。后续修改读取当前用户、同一授权版本的先前菜谱；不会读取其他用户的菜谱。结果保存为私人生成记录，只有用户选择“记录这餐”才写入饮食日志。

返回步骤、火候、可选每份营养估计、替代食材与需要另备的食材。模型生成后经过结构校验、安全审查、时间限制和已知别名的排除检查。无法匹配食物目录的配料仍可用于做法展示，但不能冒用目录 ID 记录营养。

## 模型与限制

必须配置服务端模型并取得外部 AI 授权。未配置、网络或输出验证失败时返回明确错误，不以固定菜谱伪装为 AI 生成。

营养和份量是估计；已知别名检查不等于全面成分核验，调味料成分及交叉接触仍需用户确认。自动化测试使用隔离的模型替身验证契约和错误路径，不代表供应商实际生成质量。

浏览器：启动 `python -m tests.e2e_server` 后在前端执行 `CI=1 pnpm test:e2e`。
新增用例覆盖空库存、单食材、多食材、别名去重、数量、排除项、历史隔离、后续修改及移动端表单请求。
